# Benchmark Protocol

## HumanEval
HumanEval rows use task identifiers from the benchmark source. Smoke and R4-half splits are separate; R4-half guide and eval are disjoint.

## MBPP
MBPP / EvalPlus evidence uses sanitized MBPP or EvalPlus IDs depending on protocol. Base and plus scoring fields are represented separately in `results/status/scores.csv` when available.

## LiveCodeBench
LiveCodeBench uses the active evaluator route under `workflows/evaluate/` and official code-generation metrics. It is included in smoke and R4-half split registries.

## SWE-bench-lite
SWE-bench-lite is represented in smoke split data and kept as a protocol target, even when full formal execution is outside first-stage evidence.

## smoke
Smoke protocol checks guide/eval disjointness and functionality on small task counts.

## r4_half
R4-half is the formal first-stage scoring protocol. Formal table filtering keeps only R4-half score rows from non-invalid, non-pilot, non-superseded runs.

## auxiliary_full_eval
The auxiliary_full_eval protocol uses guide subset semantics: guide is contained in full eval, heldout_eval excludes guide, and full eval equals guide union heldout. It is aggregate-only when raw evidence is missing.

## Guide/eval overlap rules
Smoke uses guide/eval disjointness. R4-half follows each manifest. Auxiliary full-eval uses guide_subset_of_full_eval and guide_disjoint_from_heldout.

## Prompt mode
Formal R4-half prompt behavior stays with the unified evaluator. Auxiliary full-eval prompt behavior is documented as a separate comparability boundary.

## Base and plus scoring
Base pass-rate and plus pass-rate occupy separate score fields. Unknown plus values remain empty rather than zero.

## partial
Partial evidence keeps its actual task count and remains visible in the registry.

## pilot
Pilot evidence remains in the full score registry but is excluded from formal tables.

## Formal table filtering
Formal rows are generated by `python workflows/aggregate/build_formal_r4_table.py --write` from `results/status/runs.csv` and `results/status/scores.csv`.

## Protocol comparability boundary
Auxiliary full-eval, diagnostic, smoke, and R4-half rows answer different questions and must not be directly ranked together.

## Flab Benchmark-Guided Quality Gate
For Flab benchmark-guided variants, capped-32 guide calibration precedes a fixed 20-task non-collapse gate. Full-guide formal evaluation is run only when the non-collapse gate passes; output collapse skips full formal evaluation.
